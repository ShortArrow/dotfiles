症状は表示のずれです。ステータスラインのアイコンより右側が 1 桁ずれ、その行
ではカーソルの位置と描かれている文字が最後まで一致しなくなります。

原因は、幅を決めるプログラムが 2 つあって、それぞれ独立に決めていることです。
Neovim は文字が何桁を占めるかを、その文字の Unicode East Asian Width
プロパティから計算します。端末は、フォントが指定した桁数でグリフを描きます。
ふつうの文字ではこの 2 つは一致します。Nerd Font はアイコンを一致しない位置の
コードポイントに置いているので、Neovim はある幅を前提に行を組み、端末は別の
幅で描きます。

## 宣言している範囲と、実際に変わるもの

`nvim/src/lua/my/fonts.lua` では `vim.fn.setcellwidths()` を使って、21 の
コードポイント範囲、合計 9,636 文字を幅 1 と宣言しています。罫線、Powerline
の記号、Devicons、Material Design Icons、Codicons です。

このうち、宣言がなければ 1 桁より広く扱われる文字がいくつあるかを数えました:

```
ambiwidth=single   9,636 文字中 45
ambiwidth=double   9,636 文字中 9,456
```

この設定では `ambiwidth` を変えていないので Neovim は既定の `single` で動いて
いて、宣言が幅を変えているのは今のところ 45 文字です。45 文字はすべて
`U+2600`〜`U+26FF` にあり、Unicode では East Asian Wide に分類されていますが、
Nerd Font は 1 桁で描きます。⛔ や ⚽ がその例です。いくつかを挙げると:

```
default        : U+26BD=2 U+26CE=2 U+26D4=2 U+26EA=2 U+26F5=2
after override : U+26BD=1 U+26CE=1 U+26D4=1 U+26EA=1 U+26F5=1
```

宣言の残り 9,591 文字は、今の設定では何も変えていません。効きはじめるのは
`ambiwidth=double` にしたときです。日本語を書く人は、罫線や幅の曖昧な約物を
揃えるためにこの設定を有効にすることが多く、そうするとこれらのアイコンは
すべて 2 桁として組まれます。同じ宣言があれば 1 桁のままです。

## 宣言が伝わるのは Neovim だけ

`vim.fn.setcellwidths()` が変えるのは Neovim の幅計算だけで、端末には何も
伝わりません。したがって宣言する値は「こうなってほしい幅」ではなく「端末が
既に描いている幅」です。目的は Neovim の行の組み方を端末の描画に合わせる
ことだからです。

その幅はフォントで決まります。Nerd Font には、アイコンが 1 セルに収まる mono
系と、アイコンがそれより広くなりうる propo 系があります。この設定は mono 系を
使っていて、`blink.cmp` にも `nerd_font_variant = "mono"` を指定しています。
propo 系のフォントでは、同じ宣言が逆方向にずれます。

## 範囲ごと宣言している理由

範囲は、実際に使っているアイコンではなく、グリフの出どころのセットごとに
区切っています:

```lua
-- Devicons
table.insert(cellwidths, { 0xe700, 0xe7c5, 1 })

-- Material Design Icons
table.insert(cellwidths, { 0xf0001, 0xf1af0, 1 })
```

Material Design Icons の範囲だけで約 110,000 文字あり、この設定で実際に使って
いるのはそのうち数十です。使っているものだけを宣言すると、新しいアイコンを
足すたびに、そのコードポイントを一覧に加えるまで表示が崩れます。範囲ごと宣言
しておけば、まだ使っていないものも含めて、フォントに入っているアイコンを
すべて押さえられます。
