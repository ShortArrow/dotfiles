ウィンドウが消えます。Alt-Tab で戻らず、タスクバーにも出ません。プロセスは
動いたままです。

GlazeWM は非アクティブなワークスペースのウィンドウを画面外へ動かしません。
DWM の cloak で隠します。cloak されたウィンドウは合成の対象から外れるだけで、
ほかは元のままです。可視で、画面内の矩形を持ち、最小化もされていません。
z オーダーを上げても変化はありません。隠しているのが z オーダーではないためです。

GlazeWM を再起動すると、シェルが報告するウィンドウを列挙します。cloak された
ウィンドウもそこに含まれますが、直前まで管理下にあったという情報は付いてきません。
管理だけが失われ、cloak は残ります。

## 意図的な再起動は稀

実際にこの状態を作るのは次の 3 つです。

- GlazeWM がクラッシュして起動し直したとき。
- モニターを挿したとき、外したとき。
- プレゼンテーションモードを on / off したとき。

後ろの 2 つは同じ事象です。ディスプレイ構成が変わると、GlazeWM はモニターと
ワークスペースの構成を作り直します。そのとき参照するのはシェルの報告で、cloak は
現在の状態としてしか読めません。誰が付けたかという情報は含まれていません。

見ていないワークスペースへウィンドウを送る設定は、どれも該当ウィンドウを増やし
ます。送られた先で即座に cloak されるためです。起動時にアプリを所定のワーク
スペースへ配置する `window_rules` が、たいていの発生源です。

## cloak を外せるのは所有プロセスだけ

別プロセスから `DwmSetWindowAttribute(DWMWA_CLOAK, 0)` を呼ぶと
`E_ACCESSDENIED` が返ります。権限の問題ではありません。GlazeWM 自身も同じ
ユーザーの非昇格プロセスで、cloak には未文書のシェル COM 経由で触れています。
その vtable レイアウトは Windows のビルドごとに変わります。汎用の復帰手段は
存在せず、復帰できるのはアプリ側に手段がある場合だけです。

wezterm にはあります。GUI プロセスごとに
`~/.local/share/wezterm/gui-sock-<pid>` へ制御ソケットを開いているので、
`WEZTERM_UNIX_SOCKET` をそこへ向ければ `wezterm cli` の宛先がそのプロセスに
固定されます。ペインを新しいウィンドウへ移すよう指示すると、ウィンドウを作るのは
wezterm 自身です。その時点で作られたウィンドウに cloak は付いていません。

`glazewm/rescue-window.ps1` は、そのプロセスが持つペインをすべて集めます。cloak
されていないウィンドウに既にあったペインも含めて、まとめて新しいウィンドウへ
移します。それ以外のアプリについては、分かっていることを表示するだけです。
アプリを再起動するか、`explorer.exe` を再起動してシェル側の cloak を全ウィンドウ
分リセットするか。

## 「管理されていない」は 3 種類ある

難しいのは復帰よりも一覧のほうです。「GlazeWM が管理していない」という条件は、
異常な状態 1 つと正常な状態 2 つを同時に拾います。

| | cloak | immersive | |
|---|---|---|---|
| 管理を失った | > 0 | いいえ | どこにも描かれない。対処すべきもの |
| 未管理だが描画済み | 0 | — | `config.yaml` の `ignore` ルール |
| サスペンド中の UWP | > 0 | はい | シェルによる cloak で GlazeWM は無関係 |

ignore ルールが未管理のウィンドウを作るのは設定どおりの動作で、UWP の cloak は
シェルによるものです。この 2 つを同じ扱いで出すと、対処すべき 1 件が十数件に
紛れます。

1 行目と 3 行目を分けるのが `IsImmersiveProcess` です。現在管理下にあるハンドルは
`glazewm query windows` が返すので、全体からそれを引きます。全体のほうは
`EnumWindows` の結果を、タイトルを持つトップレベルのうち最小化でもツール
ウィンドウでもないものへ絞ったものです。

## 既定は一覧表示

スイッチ無しで実行すると一覧を出します。復帰には `-Rescue` が必要で、一覧が
長いときのためにプロセスやハンドルでの絞り込みもあります。確認なしにペインを
動かす動作を既定にすると、元の問題より扱いにくくなります。
