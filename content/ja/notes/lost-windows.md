症状はウィンドウが消えることです。Alt-Tab に出ず、タスクバーにも並ばず、
プロセスは動いたままです。

GlazeWM は非アクティブなワークスペースのウィンドウを画面外に動かして隠すのでは
なく、DWM の cloak をかけます。cloak されたウィンドウはデスクトップの合成から
外れますが、それ以外の属性は元のままです。可視だと報告し、画面内に矩形を持ち、
最小化もされていません。z オーダーの先頭に持ってきても出てきません。隠している
のは z オーダーではないからです。

GlazeWM は起動時に、シェルが報告するウィンドウを列挙します。cloak された
ウィンドウもその一覧に入っていますが、直前まで GlazeWM が管理していたという
情報は一覧のどこにもありません。そのため、再起動すると管理だけがなくなり、
cloak は残ります。

## 何が起きると発生するか

GlazeWM を意図して再起動することは稀です。このマシンで管理を失ったウィンドウ
ができるのは次の 3 つの場面です:

- GlazeWM がクラッシュして起動し直したとき
- モニターを接続または取り外したとき
- プレゼンテーションモードを切り替えたとき

後ろの 2 つは、内部では同じ事象です。ディスプレイ構成が変わると、GlazeWM は
どのモニターとワークスペースがあるかを組み立て直します。その材料はシェルの
報告で、そこでは cloak は現在の状態でしかなく、誰がかけたかの記録はありません。

見ていないワークスペースにウィンドウを送る設定は、どれも対象のウィンドウを
増やします。送られたウィンドウは着いた時点で cloak されるからです。よくある
発生源は、起動時にアプリケーションを特定のワークスペースに置く `window_rules`
の項目です。

## cloak を外せるのは所有プロセスだけ

別のプロセスから `DwmSetWindowAttribute(DWMWA_CLOAK, 0)` を呼ぶと
`E_ACCESSDENIED` が返ります。管理者権限で実行しても変わりません。GlazeWM 自身
も同じユーザーの非昇格プロセスとして動いていて、cloak の操作には文書化されて
いないシェルの COM インターフェースを使っており、その vtable の配置は Windows
のビルドごとに変わります。したがって外から cloak を外す汎用の方法はなく、
ウィンドウを取り戻せるのは、そのアプリケーション自身に入口がある場合だけです。

wezterm にはあります。wezterm の GUI プロセスは 1 つずつ
`~/.local/share/wezterm/gui-sock-<pid>` に制御ソケットを持っていて、
`WEZTERM_UNIX_SOCKET` にそのパスを設定すると、`wezterm cli` はそのプロセスと
通信します。ペインを新しいウィンドウへ移すよう指示すると wezterm 自身が
ウィンドウを作り、そのとき作られたウィンドウには cloak がかかっていません。

`glazewm/rescue-window.ps1` はこれを使います。そのプロセスが持つペインを、正常に
描かれているウィンドウにあるものも含めてすべて集め、新しいウィンドウに移し
ます。それ以外のアプリケーションについては、分かっていることを表示して終わり
ます。アプリケーションを再起動するか、`explorer.exe` を再起動してシェルの
cloak を全ウィンドウ分まとめてリセットするか、のどちらかです。

## 「管理されていない」には 3 つの意味がある

難しいのは復帰よりも、対象のウィンドウを一覧にすることでした。「GlazeWM が
このウィンドウを管理していない」という条件は、異常な 1 つの場合と、正常な 2 つ
の場合に当てはまります:

| | cloak | immersive | |
|---|---|---|---|
| 管理を失った | > 0 | いいえ | どこにも描かれない。対処が要るもの |
| 未管理だが描画されている | 0 | — | `config.yaml` の `ignore` ルールに当たる |
| サスペンド中の UWP アプリ | > 0 | はい | シェルが cloak したもので GlazeWM は無関係 |

[このマシン](/ja/machine/)では `ignore` ルールが 11 プロセスに当たり、UWP
アプリはシェルによって絶えずサスペンドされ cloak されています。この 3 つを
同じ扱いで一覧に出すと、対処が要る 1 件が、対処の要らない十数件の中に埋もれ
ます。

1 行目と 3 行目を分けるのは `IsImmersiveProcess` です。GlazeWM が今管理している
ウィンドウは `glazewm query windows` で得られるので、そのハンドルを全体から
引きます。全体は `EnumWindows` の結果を、タイトルのあるトップレベルウィンドウ
のうち、最小化されておらずツールウィンドウでもないものに絞ったものです。
