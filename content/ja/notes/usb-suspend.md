2026 年 6 月下旬、2.4GHz の無線マウスが操作中に切れるようになりました。同じ
時期に USB オーディオも不調になっています。

## 空のログが手がかりだった

Windows はデバイスの着脱を Kernel-PnP のイベント ID 410 / 411 に記録します。
物理的に接触が切れれば必ず出るものです。期間全体を通して、これが 1 件もありま
せんでした。

この不在ひとつで、ケーブル、ポート、レシーバ、コネクタが候補から消えます。
どれが壊れても記録されるはずのものだからです。残るのは無線リンクと、その上に
乗っている電源ポリシー。

## 2 年間なにも変えていない、そして日付

机の上は 2 年間そのままです。同じレシーバ、同じポート、同じ配置。だから問いは
「ソフト側で何がいつ変わったか」になります。

`2026-06-22 12:37` に KB5094126 が適用され、同じ分に USB と HID のドライバ
スタックが差し替わっていました。`usbxhci`、`usbhub3`、`usb.inf`、`input.inf`、
`hidusb`。症状が出始めたのはその日です。

時刻の一致は原因ではありません。どこを見ればいいかが決まるだけです。指していた
のは、新しいスタックが従うようになった 2 つの設定でした。電源プランの USB
セレクティブサスペンドと、デバイスごとの「電力の節約のためにコンピューターで
このデバイスの電源をオフにできるようにする」。

両方を切ると切断は止まりました。

## スクリプトがやること

`windows/usb/fix-usb.ps1` は、USB セレクティブサスペンドの AC / DC インデックス
を 0 にしたあと、`root/wmi` の `MSPower_DeviceEnable` を走査して、名前に USB を
含むインスタンスのフラグを落とします。

`restore-usb.ps1` は Windows 既定へ戻します。どちらも「これから変える先とは違う
状態」のデバイスだけを対象にするので、2 回走らせても 2 回目は何も起きません。

## 直ったままではなかった

同じマシンで 2026-08-02 に測った値:

| | |
|---|---|
| USB セレクティブサスペンド AC / DC | `1`（Windows 既定） |
| 電源オフを許可されている USB デバイス | 13 / 13 |

`fix-usb.ps1` が変えたものは全部、元の位置に戻っています。ドライバファイルの
日付は 2026-07-15。`hidusb.sys` が 10.0.26100.8875、`usbxhci.sys` が
10.0.26100.8521 で、7 月の累積更新がスタックを 2 度目に差し替えた分です。

読み解けるのはデバイスごとのフラグのほうです。セレクティブサスペンドは電源
プランに属するので、プランを切り替えただけならその 1 行しか説明できず、13 台の
フラグは無傷のはずでした。13 台とも既定に戻っているということは、電源プラン
ではなくデバイススタックが入れ直されたということです。

つまりこの対処には累積更新いくつ分かの寿命があり、期限切れに誰も気付いていま
せんでした。`windows/doctor.ps1` がこの 2 つの値を出すようにしたので、次に走ら
せたときには見えます。
