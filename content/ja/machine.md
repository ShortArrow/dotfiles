ノートに出てくる時間や文字数は、全部このマシンで測っています。

| | |
|---|---|
| OS | Windows 11 Pro, build 26200 |
| CPU | Intel Core 9 270H, 14 コア / 20 スレッド |
| メモリ | 32 GB |
| システムボリューム | `C:` NTFS, 1.8 TB |
| 作業ボリューム | `V:` ReFS, 400 GB, Dev Drive |
| シェル | PowerShell 7.6 / WezTerm |
| もう一つの環境 | WSL 2 上の Arch |

リポジトリは `V:` に置いてあります。各ツールの設定ファイルは、そこから symlink を
張って配ります。

## 数値を左右する 2 つの事情

**エンドポイント保護が集中管理されていて、切れません。** プロセスを 1 つ作るたびに
検査が走り、しかも同期なので待たされます。ふつうなら数ミリ秒のところが 150 ms
前後になります。プログラムが別のプログラムを起動する形にすると、経由した数だけ
検査を通ります。[shim をやめて symlink で起動する](/ja/notes/shim-cost/)に書いた
127 ms も、検査のないマシンならもっと小さいはずで、そうなると shim をやめる意味
自体が薄くなります。

**`V:` は信頼済みの Dev Drive です。** 信頼フラグを立てる前は、同じボリュームに
1 回書き込むのに 500 ms ほどかかっていました。ビルドが壊れたのかと思う遅さです。

`PATH` の文字数、shim の本数、shim が 1 回で起動するプロセス数。この 3 つはどちらの
事情とも無関係なので、同じツールが入っていればどのマシンでも同じ値になります。
