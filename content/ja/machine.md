ノートには所要時間や文字数が出てきます。すべてここで測ったものです。

| | |
|---|---|
| OS | Windows 11 Pro, build 26200 |
| CPU | Intel Core 9 270H, 14 コア / 20 スレッド |
| メモリ | 32 GB |
| システムボリューム | `C:` NTFS, 1.8 TB |
| 作業ボリューム | `V:` ReFS, 400 GB, Dev Drive |
| シェル | PowerShell 7.6 / WezTerm |
| もう一つの環境 | WSL 2 上の Arch |

リポジトリのチェックアウトは `V:` にあり、配置されるものはすべてそこからの
symlink です。

## 数値が依存している 2 つの事実

**エンドポイント保護が集中管理されていて、プロセス生成のたびに検査が入ります。**
無効化はできません。検査は同期なので、プロセス生成 1 回のコストが数ミリ秒から
150 ms 前後まで上がります。プログラムを別のプログラム経由で起動する構成は、
その分を段数だけ払います。この検査が無いマシンなら、
[shim をやめて symlink で起動する](/ja/notes/shim-cost/)に書いた 127 ms は
もっと小さく、あの構成を採る理由もかなり弱くなります。

**`V:` は信頼済みの Dev Drive です。** 信頼フラグが無いと同じボリュームで 1 回の
書き込みに約 500 ms かかりました。ビルドが壊れたように見える速度です。

どちらにも依存しない数値もあります。`PATH` の文字数、shim の本数、shim が起動する
プロセス数。これらは同じツールが入っていればどこでも同じです。
